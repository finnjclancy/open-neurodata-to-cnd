## Two compatibility bugs found by actually loading the MAT files

1. Scalar stimulus features had been written as `1 × time` rows. Python's reader
   squeezed these into vectors, hiding the error. They now serialize as
   `time × 1` columns, as the upstream scripts expect. Pipeline features also explicitly
   use columns, and the converter dependency is now pinned to the published
   revision containing the serialization and coordinate-export improvements.
2. Newly exported external channels were a plain MATLAB struct. Upstream CNSP
   accesses cell groups with braces. New exports now use a cell containing a group
   struct. Legacy input layouts remain supported. When editing an existing
   single-group template through MNE, pass `cnsp_external_cells=True` to
   `write_cnd` to explicitly normalize it; the default preserves its layout.

Regression tests inspect the serialized MATLAB types and dimensions directly.

## Upstream TRF execution

Source: https://github.com/CNSP-Workshop/CNSP-resources

Pinned revision: `74d26e5b7ded8eb80f56aa26517b7e73ba4a83a7`.
No upstream source files were edited. A separate harness calls the bundled
`mTRFpartition`, `mTRFcrossval`, `mTRFtrain`, and `mTRFpredict` functions.
The entire continuous run is divided into five analysis blocks; four are used
for cross-validation and training, the fifth is held out. Storage remains one
trial. Lags are 0–200 ms, lambda candidates are 0.1, 1, 10. Raw source sampling

## MATLAB preprocessing and TRF validation

All 240 final recordings passed `scripts/validation/check_matlab_cnsp.m` using
MATLAB R2026a Update 5 with Signal Processing Toolbox. The driver calls unchanged
upstream CNSP functions for 8 Hz low-pass filtering of EEG and EOG, downsampling
to 64 Hz, 1 Hz high-pass filtering, bad-channel detection/interpolation,
average referencing, and stimulus downsampling. It then runs mTRF
cross-validation, training and held-out prediction with lags -100 to 600 ms.
The corrected driver explicitly uses ridge regularisation for both
cross-validation and final training, with the same lambda candidates. Each
result records the method, four training blocks and held-out block 5.
The original run used default ridge cross-validation but Tikhonov final
training; its scores have been superseded and remain only as an audit trail.

The corrected 20 September rerun passed all 240 recordings (40 per task), with
finite model weights and reported correlations. Every input hash matches the
previous corpus. The six earlier single-feature MATLAB pilots were also rerun
successfully in `giovanni-validation/matlab-preprocessing-ridge/`. A fresh P3
recording converted through the clean wheel installation passed the corrected
MATLAB workflow too. The [full-corpus audit](giovanni-validation/matlab-full-corpus-ridge/audit.json)
records coverage, source-script hashes and the summary hash.

These are compatibility checks, not evidence of statistical significance or
validated predictive utility. Each recording contributes four training blocks
and one held-out block. Preprocessing occurs before blocking; these checks are
not a leakage-controlled or independent participant-level performance evaluation.

The original tutorial scripts have not been run unchanged. This configured
driver makes the dataset-specific choices Giovanni asked us to identify:

- Local dataset paths and platform-compatible path separators.
- Average reference instead of the tutorial's mastoid assumption: ERP CORE's
  external channels are EOG and must not be treated as mastoid references.
- All declared stimulus features as separate predictors. A single feature can
  be absent from an equal time block in some recordings, which makes that split
  unsuitable for cross-validation.
- Removal of the idle tail after the final event while retaining the complete
  600 ms positive-lag response window, followed by five analysis blocks.
- A common 64 Hz analysis rate. These pilots start at 1024 Hz, giving the integer
  ratio required by upstream `cndDownsample`. Arbitrary separate source clocks
  still require an appropriate resampling choice.

No upstream source was edited. Logs, input SHA-256 hashes, pinned upstream
revision, MATLAB version and per-recording results are in
`giovanni-validation/matlab-full-corpus-ridge/`. Reproduce from the pipeline repo:

```sh
PATH=/Applications/MATLAB_R2026a.app/bin:$PATH python3 scripts/validation/run_validation.py --data-root outputs/nm000132/0.4.0/recordings --all-recordings --upstream ../tmp/CNSP-resources --output docs/reports/giovanni-validation/matlab-full-corpus-ridge --engine matlab --preprocess
```

The original tutorial scripts themselves are interactive and path-specific; the
driver preserves the upstream processing/model functions and records the
dataset-specific choices required to run them on ERP CORE.
